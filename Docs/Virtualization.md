# Omabox guest runtime

Omabox uses Apple's Virtualization framework directly. The app does not launch QEMU, emulate an Intel CPU, or embed a browser. The guest is native aarch64 Linux with a Virtio graphics framebuffer, block storage, networking, sound, sockets, and file sharing.

The current desktop renders OpenGL through Mesa llvmpipe on the guest CPU. The host's glass interface is independent of guest graphics. Apple documents the Linux Virtio graphics configuration but exposes no Linux 3D renderer selection. Omabox disables expensive guest blur, shadows, and animations by default and must not advertise hardware acceleration for Linux graphics. [Apple Linux graphics configuration](https://developer.apple.com/documentation/virtualization/vzvirtiographicsdeviceconfiguration)

## Verified upstream inputs

The bootstrap starts from the immutable Try Omarchy v0.3.0 release, verified against SHA-256 `e89d71e8c409bdb28f7f60299eb18854ea4e6f2b01d5c1bb03f5d7d49ac9ba77`. That release contains Omarchy 4.0.2 at commit `346e69e1cec6c4e8924531874af6ba010a1bc99e`, Linux `7.2.2-2-aarch64-ARCH`, a 6 GiB ext4 factory disk, and a matching direct-boot kernel/initramfs. Every supplied artifact is independently checked against the factory manifest. [Try Omarchy release](https://github.com/omacom/try-omarchy/releases/tag/v0.3.0), [factory contract](https://github.com/omacom/try-omarchy/blob/v0.3.0/guest/spec.json)

Try Omarchy normally runs that guest using QEMU with Apple Hypervisor for CPU execution and VirGL/ANGLE/Metal for graphics. Omabox reuses its unprovisioned guest factory and adapts a separate writable copy for Apple's device model. It never reads or changes a Try Omarchy user's VM. [Try Omarchy architecture](https://github.com/omacom/try-omarchy/blob/v0.3.0/docs/architecture.md)

The upstream Omarchy distribution does not currently publish an official aarch64 ISO/package repository. This is an adapted ARM guest, not an official Omarchy installation image. Omarchy 4's source is largely architecture independent, but its default package sources still target the upstream distribution's supported architecture. [Upstream ARM discussion](https://github.com/omacom/omarchy/discussions/7956), [upstream package configuration](https://github.com/omacom/omarchy/blob/quattro/default/pacman/mirrorlist-stable)

## Build and install

Run `Scripts/prepare-guest.sh` on an Apple silicon Mac before generating the Xcode project. The script downloads the pinned DMG, verifies the complete source artifact, mounts it read-only, decompresses a fresh sparse disk, and boots that copy using the small signed `GuestBootstrap` tool. A root maintenance boot applies only the Omabox overlay. The guest then syncs, remounts its root read-only, and powers off before hashing and publishing the template.

Generated assets are `Omabox/Resources/Guest/kernel`, `initramfs`, `rootfs.raw`, and `metadata.json`. They are excluded from Git. The bundle also includes original provenance, package inventory, Omarchy license, and build specification. `metadata.json` includes exact sizes and SHA-256 hashes. These assets must be included as a folder reference so their `Guest` directory survives app packaging.

The Swift installer validates the template, makes a private APFS clone or sparse copy in its application container, expands its logical disk size, and atomically publishes the installation. A subsequent app launch reuses that disk. It validates immutable boot files without comparing the mutable guest disk to its factory hash. The existing upstream growfs service expands ext4 to the selected capacity at boot. The factory has no user account or shared password; Omarchy's first-owner screen creates the owner's account.

App updates and guest updates are separate. The direct-boot kernel and Omabox's external sound module remain paired. Never replace an existing guest's root disk with a newer factory. Updating the guest kernel requires a tested boot-kit and module migration.

## Guest adaptations

The upstream kernel enables Virtio graphics, sockets, and file sharing, but disables `CONFIG_SND_VIRTIO`. The bootstrap compiles the original Linux v7.2.2 sound driver against the factory's matching kernel headers. Its source is pinned to stable-kernel commit `52c36105f76e96b638152a42e735f2e7767ed946`; source hashes and GPL license material live in `Guest/virtio-sound-source`. No kernel or compositor source is modified by this adaptation. [Linux Virtio sound source](https://github.com/gregkh/linux/tree/52c36105f76e96b638152a42e735f2e7767ed946/sound/virtio)

The guest mounts the user-selected share at `/mnt/omabox` using VirtioFS. The host's file selection controls the shared boundary. The guest never receives the host's home directory implicitly. [Apple directory sharing](https://developer.apple.com/documentation/virtualization/sharing-files-between-a-linux-virtual-machine-and-macos)

The host passes display scale and the chosen software-rendering thread count as validated `omabox.display_scale` and `omabox.render_threads` boot arguments. The guest applies these on each desktop start. User overrides live in `~/.config/omabox/desktop.env` and `~/.config/omabox/hyprland.lua`; both are created once and then preserved. The environment file starts empty so future host setting changes take effect. Its literal `KEY=VALUE` entries override host defaults, and the user's Lua runs last. The initial Lua contains the editable blur, shadow, and animation defaults. `~/.config/omabox/desktop.env` does not execute shell commands or expand variables.

The display service follows DRM hotplug events and reads fresh preferred timings through the installed libdrm. Aquamarine 0.14 caches the modes of an existing connector, so simply requesting a new Apple display size or reloading Hyprland leaves the desktop at its old resolution. Omabox applies the updated numeric modeline while preserving the current display scale. Events are coalesced during a window resize, and the service does no periodic work while idle. Linux's CVT mode generation rounds horizontal pixel counts down to a multiple of eight. [Aquamarine connector handling](https://github.com/hyprwm/aquamarine/blob/v0.14.0/src/backend/drm/DRM.cpp#L1063), [Hyprland preferred-mode selection](https://github.com/hyprwm/Hyprland/blob/v0.56.1/src/output/Monitor.cpp#L773)

Hyprland 0.56.1 truncates fractional modeline clocks before converting MHz to kHz. Omabox rounds to the nearest integer MHz while preserving exact display geometry. Its approach follows the pinned Try Omarchy display-cache workaround, using libdrm's public ABI instead of copying the upstream EDID parser. The service uses the guest's existing libdrm, systemd/udev, and Hyprland packages. [Hyprland clock parser](https://github.com/hyprwm/Hyprland/blob/5c9377c15f85c50648f35ca5a213754f95b93ca0/src/config/shared/monitor/Parser.cpp#L50), [upstream workaround](https://github.com/omacom/try-omarchy/blob/6aced581ad991b0a1495b74907f8a41c8a58d0b6/guest/native-overlay/usr/local/bin/omarchy-native-display-sync), [libdrm ABI](https://gitlab.freedesktop.org/mesa/drm/-/blob/main/xf86drmMode.h)

Set `OMABOX_DYNAMIC_RESOLUTION=0` in `~/.config/omabox/desktop.env` to use a manually configured resolution. The service rechecks this setting on display events, so removing it or setting it to `1` resumes automatic resizing with the next event. Explicit per-output monitor rules retain priority over Omabox's catch-all rule.

Clipboard sharing uses the Omabox Wayland agent because the usual SPICE desktop agent assumes an X11 session. The guest listens on Virtio socket port 4040 and sends a version-1 greeting. Both directions carry bounded newline-delimited JSON text messages, with a 64 KiB UTF-8 text limit. The agent uses Wayland clipboard events, accepts only the host CID, suppresses echo loops, and establishes a fresh baseline at each connection. Existing clipboard content is not sent when sharing is enabled. [Wayland clipboard integration limitations](https://github.com/ggalancs/omarchy-arm-utm#clipboard-and-shared-folder)

## Validation and distribution

Run `Scripts/check-guest.sh` for the native integration suite. It verifies the factory hashes, creates a disposable clone, provisions a test-only account there, then boots a real SDDM/uwsm/Hyprland/Quickshell session. It checks the active compositor and portal services, an error-free Hyprland configuration, VirtioFS mount, native Virtio sound playback device, and both clipboard directions through the host's actual VZ socket. A further restart verifies user display/thread overrides and checks that both edited configuration files remain byte-for-byte unchanged. It exports desktop screenshots and runtime reports and shuts down all test boots cleanly. The test account and its generated credentials never enter the factory or the user's installation.

This suite passed on September 11, 2026. The rendered desktop used a 1440 × 900 Virtio scanout; the Hyprland screen-copy portal and PipeWire were active. Clipboard protocol unit tests also passed inside Linux. Microphone capture, host keyboard routing, and native app UI behavior require the app's separate interactive checks. These checks demonstrate working behavior on the test machine, not a general performance guarantee.

`python3 Scripts/QA/check_reliability.py` checks native display resizing, repeated pause/resume, NAT DNS and certificate-verified HTTPS, rejected writes through a host read-only share, durable writable-share content across distinct Linux boots, and PCM delivery through Virtio sound. The helper configures a nil audio sink, which Apple's SDK documents as discarding guest audio. These tests verify PCM acceptance and drain without playing through Mac speakers or attaching a microphone. The separate display-service fixture checks startup catch-up, scale preservation, user opt-out, and coalescing rapid size changes. Reports distinguish the regenerated factory from existing app-private VM disks, which remain untouched.
